# 嵌入窗口尺寸：客户区与窗口矩形

> 文档对应代码：`AvaloniaEmbedExe/NativeExe/ExternalAppHost.cs`、`AvaloniaEmbedExe/NativeExe/ContainerWindow.cs`

## 1. 概念：一个窗口的两个矩形

```
┌──────────────────────────────────────────┐  ← 窗口矩形 GetWindowRect
│                                          │      外部边框（非客户区）
│  ┌────────────────────────────────────┐  │
│  │           标题栏 Title Bar          │  │      非客户区
│  ├────────────────────────────────────┤  │
│  │           菜单栏 Menu（20px）       │  │      非客户区
│  ├────────────────────────────────────┤  │
│  │                                    │  │
│  │      客户区 Client Area            │  │  ← 客户区 GetClientRect
│  │        （应用内容排版区域）          │  │      (0,0 是客户区左上角)
│  │                                    │  │
│  │                                    │  │
│  └────────────────────────────────────┘  │
│                                          │  ← 内部边框（非客户区）
└──────────────────────────────────────────┘
```

| 矩形 | 代表什么 | 含什么 | 代码里的量法 |
|---|---|---|---|
| **窗口矩形** | 窗口整体占的屏幕区域 | 客户区 **+** 全部非客户区（标题栏/边框/菜单/滚动条） | `GetWindowSizePx`：`GetWindowRect` 的 right-left / bottom-top（`ExternalAppHost.cs:679`） |
| **客户区** | 应用真正画内容的区域 | 只算客户区 | `GetClientSizePx`：`GetClientRect` 的 right-left / bottom-top（`ExternalAppHost.cs:684`） |

关系恒等式：

```
窗口矩形 = 客户区 + 非客户区
```

（`GetNonClientOverheadPx` 就是按这个差算的，`ExternalAppHost.cs:452`）

## 2. 嵌入流程里两者各管什么

流程主体：`EmbedIntoContainerAsync`（`ExternalAppHost.cs:347`）

### 步骤 2：SetParent 后、未摘装饰时

此时量到的客户区是**程序自己排版用的尺寸**，作为后续目标。

```
┌────────────────────────────┐
│ 标题栏                     │ ┐
├────────────────────────────┤ │ 非客户区
│ 菜单栏 20px                │ ┘
├────────────────────────────┤
│                            │
│   客户区 212 x 264         │  ← desiredClient
│   （程序自己排版用的尺寸）    │     WaitForStableClientSizeAsync 量到的
│                            │     是"客户区"，不是窗口矩形
└────────────────────────────┘
```

### 步骤 4-5：摘掉装饰 + ApplyFrameChanged 后

`ApplyFrameChanged` 带 `SWP_NOSIZE`：**窗口矩形保持不变**，让出来的装饰空间全部变成客户区。
实测 calc1.exe：窗口 228x323 / 客户区 212x264，摘掉装饰后窗口仍是 228x323，而客户区涨到 228x303。
程序内容只按 212x264 排版，于是右边多出 16px、下边多出 39px 的死白边——这就是"嵌入窗口大小设置得不对"。

### 步骤 5：重新定尺寸

重算后**残留的非客户区**（calc1.exe 是 20px 高的菜单条）要加回去，客户区才能恰好落在 desiredClient 上。

```
目标窗口矩形 = desiredClient + 残留非客户区 (0 x 20) = 212 x 284

┌────────────────────────────┐
│ 菜单栏 20px（残留）          │  ← 非客户区（摘不掉的部分，要加回去）
├────────────────────────────┤
│                            │
│   客户区 212 x 264         │  ← 恰好等于 desiredClient，内容不用重排
│                            │
└────────────────────────────┘
```

> 注：212x284 也正是把窗口交给 calc1.exe 自己调整时它最终收敛到的尺寸，两条路算出同一个数，可以互相印证。

代码对应（`ExternalAppHost.cs:382-392`）：

```csharp
var (nonClientWidth, nonClientHeight) = GetNonClientOverheadPx(hwnd);   // 残留装饰
int targetWidth = desiredClient.width + nonClientWidth;                 // 客户区 + 装饰
int targetHeight = desiredClient.height + nonClientHeight;              // = 窗口矩形
PInvoke.SetWindowPos(hwnd, HWND.Null, 0, 0, targetWidth, targetHeight,
    SET_WINDOW_POS_FLAGS.SWP_NOMOVE | SET_WINDOW_POS_FLAGS.SWP_NOZORDER |
    SET_WINDOW_POS_FLAGS.SWP_NOACTIVATE);
```

## 3. 为什么"自然尺寸"返回的是窗口矩形

`EmbedIntoContainerAsync` 最后返回 `GetWindowSizePx(hwnd)`（`ExternalAppHost.cs:392`）——是**窗口矩形**而不是客户区，原因：

1. 控件要占的大小 = 外部窗口嵌入容器后整体占的空间，包括残留的菜单条那 20px——量客户区会少算一块。
2. `MeasureOverride` 再把它除以 `RenderScaling` 转成 DIP（`ExternalAppHost.cs:542-546`）交给 Avalonia 布局。
3. 兜底逻辑也是这个方向：客户区量不到（窗口销毁时 `GetClientRect` 返回 (0,0)）就退到窗口矩形（`ExternalAppHost.cs:437-441`），保证控件不会算出 0 尺寸。

## 4. 一处容易混淆的命名

`ContainerWindow.ClientSizePx`（`ContainerWindow.cs:86-89`）名字叫"客户区"，实现却用 `GetWindowRect`——但容器是**无边框 WS_CHILD 空窗口，没有非客户区**，两个矩形相等，所以名称和实现并不矛盾。它量的是"容器有多大"，供居中偏移计算用。

## 5. 尺寸换算速查

| 场景 | 用什么 | 原因 |
|---|---|---|
| 应用自身排版的目标尺寸 | 客户区（`GetClientRect`） | 内容按客户区排版 |
| 嵌入后控件应占的尺寸 | 窗口矩形（`GetWindowRect`） | 含残留非客户区，整体占空间 |
| 非客户区开销 | 窗口矩形 − 客户区 | 恒等式差分 |
| 兜底（窗口已销毁） | 窗口矩形 | 客户区量不到时避免 0 尺寸 |
